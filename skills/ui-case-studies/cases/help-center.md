# Case study — Help center / docs (in-product)

Sources: [Customer portal UX](https://vezert.com/blog/saas-customer-portal-design-best-practices).

## Job

Deflect support: find answers in context of the current feature, then escalate if needed.

## Default blocks

1. **Search** — fast, typo-tolerant
2. **Contextual articles** — suggested by current page/feature
3. **Categories** — Getting started, Billing, Troubleshooting…
4. **Article body** — title, updated date, steps, screenshots/video optional
5. **Was this helpful?** — yes/no + optional feedback
6. **Escalate** — contact support / chat (with human handoff)
7. **Status** link if you have an incident page

## Content defaults

| Area | Expected |
|------|----------|
| Empty search | “No articles” + browse categories ([search-results](search-results.md)) |
| Article | Short answer first, then detail |
| Contact | Pre-fill page URL / product area when opening a ticket |

## Defaults

- Prefer in-product help over only shipping users to an external site
- AI chat optional; always offer human escalation

## Anti-patterns

- Docs only as a footer link with no search
- Ticket form with 20 required fields
- Outdated articles with no “updated” date

## Checklist

- [ ] Search + categories + article
- [ ] Contextual suggestions when possible
- [ ] Escalation path from help UI
