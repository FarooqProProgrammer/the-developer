# Case study — Onboarding / setup checklist

Sources: [SaaSUI onboarding flows](https://www.saasui.design/blog/saas-onboarding-flows-that-actually-convert-2026).

## Job

Get a new user to first value fast — adapt to role/intent; don’t dump the whole product.

## Default patterns

1. **Intent / role question** (≤3–5 options) early — drives which checklist and home modules appear
2. **Progressive checklist** — 3–7 steps, time estimates (“2 min”)
3. **Auto-detect** completed steps from real actions (don’t force re-clicks)
4. **Dismissible + recoverable** — close checklist; reopen from a persistent entry
5. **Progress** — % or N of M; celebrate completion once

## Content that should appear

| Area | Expected content |
|------|------------------|
| Checklist title | “Get started” / “Finish setup” |
| Each step | Action label + why it matters (one line) |
| Primary step CTA | Goes to the exact screen to complete it |
| Skip | Optional soft skip; don’t block core product forever |

## Defaults

- Hide irrelevant features for the chosen role (don’t gray them out forever)
- Surface advanced tips later (progressive disclosure), not day one
- Empty dashboard + checklist beats empty charts with fake zeros

## Anti-patterns

- 15-step mandatory wizard before any product use
- Checklist that doesn’t update when user already did the task
- Same onboarding for admin and end-user
- Blocking modal on every login

## Checklist

- [ ] ≤7 setup steps for the default persona
- [ ] Steps auto-complete from product events
- [ ] User can dismiss and return
- [ ] Completion state clears the widget
