---
name: prototype
description: Build a throwaway prototype before implementing a change
---

Load and follow the `prototype` skill.

For every change request (feature, behavior, or UI), prototype first:

1. Name the single question the prototype must answer.
2. Pick LOGIC (state/business model) or UI (look/feel variants).
3. Build throwaway, trivial-to-run code near the real module/page.
4. Get a verdict from the user before production implementation.

Skip only for pure docs, typos, reviews, commits, or when the user explicitly says to skip the prototype.
